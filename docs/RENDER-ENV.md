# Render environment: copy-paste reference

Use this when creating the Render **Web Service** and pasting variables into
**Environment → Add from .env** (Render accepts dotenv format).

- If you deploy via the **Blueprint** (`render.yaml`), every variable below is
  already defined. You only need to type the **5 secrets** marked **[SECRET]**.
- **Do not set `PORT`** on Render — it injects its own `PORT` and routes to it.

---

## The only 5 values you must supply

| Variable | Where to get it |
| --- | --- |
| `DATABASE_URL` | Supabase → Project Settings → Database → Connection pooling (port `6543`); replace `<password>` |
| `DIRECT_URL` | Supabase → Database → Direct/session connection (port `5432`); replace `<password>` |
| `SESSION_SECRET` | Auto-generated by the Blueprint; if manual, run `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase → Project Settings → API → `service_role` (reveal) |
| `FRONTEND_URL` / `PUBLIC_API_URL` | Your Vercel URL and Render URL |

---

## Bulk block (paste into Render → Environment → Add from .env)

Replace every `<...>` placeholder. The shared DB password is the one from your
Supabase project.

```env
NODE_ENV=production
FRONTEND_URL=https://<your-app>.vercel.app
CORS_ORIGINS=

DATABASE_URL=postgresql://postgres.iurbtarvbtspgmuqgfip:<DB_PASSWORD>@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=10
DIRECT_URL=postgresql://postgres.iurbtarvbtspgmuqgfip:<DB_PASSWORD>@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres

SESSION_SECRET=<48-byte-hex-secret>
ACCESS_TOKEN_TTL=15m
REFRESH_TOKEN_TTL_DAYS=30

STORAGE_PROVIDER=supabase
SUPABASE_URL=https://iurbtarvbtspgmuqgfip.supabase.co
SUPABASE_STORAGE_BUCKET=sail-media
SUPABASE_SERVICE_ROLE_KEY=<service-role-key>

PUBLIC_API_URL=https://sail-api.onrender.com
UPLOAD_DIR=uploads
UPLOAD_MAX_MB=8

WEATHER_PROVIDER=open-meteo
```

> The `sail-media` bucket already exists and is public. Uploads land in
> `sail-media/images/` and `sail-media/documents/`.

## Service settings (match the Blueprint)

| Setting | Value |
| --- | --- |
| Environment | Node |
| Region | Singapore |
| Branch | `main` |
| Build Command | `npm install && npm run db:generate -w backend && npm run db:deploy -w backend && npm run build -w backend` |
| Start Command | `npm run start -w backend` |
| Health Check Path | `/api/v1/health` |

After the first deploy, copy the service URL into `VITE_API_URL` on Vercel
(`https://<service>.onrender.com/api/v1`) and set `PUBLIC_API_URL` here to the
same base URL (no `/api/v1` suffix).
